# Macカメラ動作確認UI

Macのブラウザでカメラ画像を共通Workerへ送り、スマホ保持・2秒の継続判定・通知を確認するための簡易UIです。製品用のWeb画面とは別に使えます。

## 起動

リポジトリ直下の `cloudflare/.env.connection` に次の接続設定を置きます。このファイルはGit管理対象外です。実際のトークンはチームの共有経路で受け取ってください。

```dotenv
FOCUS_API_URL=https://focus-shared-api-20261018.take-otani.workers.dev
FOCUS_API_TOKEN=replace-with-worker-token
```

```sh
npm run start:mac-check
```

表示された `http://127.0.0.1:3000` をChromeまたはSafariで開きます。ポートが使用中なら `MAC_CAMERA_PORT=3001 npm run start:mac-check` で変更できます。

1. 画面の開始ボタンを押し、ブラウザのカメラ許可を選びます。
2. カメラに手元を映し、スマホを持たない状態と持つ状態を比べます。
3. 新しい画像で2秒以上の継続保持が確認されると、画面に通知が出ます。音は画面で切り替えられます。
4. 一時停止・終了でカメラと撮影を止めます。別タブへの移動など画面が非表示になった場合も停止します。

既定のセッションは3分で終了します。カメラは開始操作まで有効になりません。カメラ許可が拒否された場合は、ブラウザのサイト設定とmacOSの「システム設定 → プライバシーとセキュリティ → カメラ」で使用ブラウザを確認してください。

## dots・遠隔操作を使う場合

既存の判定APIとは別の[Events Worker](../../cloudflare-events/README.md)を使います。`cloudflare/.env.connection` に次を追加してローカルサーバーを再起動します。未設定なら従来のカメラ確認だけを利用できます。

```dotenv
FOCUS_EVENTS_URL=https://focus-events-20261018.take-otani.workers.dev
FOCUS_EVENTS_TOKEN=replace-with-events-worker-ingest-token
FOCUS_SOURCE_ID=00000000-0000-4000-8000-000000000001
FOCUS_DEVICE_ID=mac-demo-1
```

`FOCUS_EVENTS_TOKEN` はEvents Workerの `INGEST_TOKEN` と同じ値で、判定APIの `FOCUS_API_TOKEN` とは別です。`FOCUS_SOURCE_ID` は自分のプロフィール用に一度生成したUUIDへ置き換えます。複数端末をまとめて操作するときは同じsource ID、端末ごとに異なるdevice IDを設定してください。`FOCUS_DEVICE_ID` を省略するとsource IDを使うため、複数端末では明示的に設定します。

このトークンはsourceを指定できる管理用の共通資格情報です。信頼するローカルサーバーだけに設定し、フロントエンドのソースやGitへ入れないでください。

### dotsとの接続

1. カメラ確認UIの接続リンク、または `http://127.0.0.1:3000/mcp/setup` を開きます。
2. ChatGPTのPluginsからカスタムMCPサーバーを追加し、画面の `/mcp` URLとOAuth認証を指定します。クライアント登録はDCRで行います。
3. ローカル画面でペアリングコードを発行し、WorkerのOAuth画面で入力します。コードは10分間・1回限りです。
4. OAuth画面に表示された読取・イベント購読・監視制御の権限を確認して接続します。コードは他の人と共有しないでください。
5. dotsでFocusを有効にし、次のように依頼します。

> Focusのfocus.phone_heldを購読して、イベントが届いたらスマホを置いて集中に戻るよう一言で知らせて。解除するまで監視して。

接続設定ページではカメラを起動しません。カメラ確認画面へ戻り、表示したまま検知を試してください。検知された新しい通知のメタデータだけを非同期送信します。画像はEvents Workerやdotsへ送りません。Macの即時通知とdotsの通知には時間差があります。

購読を止める場合はdotsへ解除を依頼します。購読解除は撮影を止める操作ではないため、撮影を止める場合は確認UIで終了するか遠隔OFFを指示します。接続を取り消した場合、そのOAuth認可でのイベント配送も無効になります。

### Web画面やdotsから別の端末をON/OFFする

監視を受ける端末で、確認画面の「このMacの遠隔操作を許可」を押します。初期状態は未許可です。許可操作ではブラウザのカメラ権限を確認するため一度カメラを取得してすぐに止め、ON指示を受けるまで画像を送信しません。「許可を解除・停止」で遠隔許可と撮影を止めます。

Web画面の端末一覧、またはdotsから同じsourceの別端末を選んで監視ON/OFFを指示します。dotsへの依頼例です。

> Focusの監視デバイス一覧を取得して、mac-demo-1の監視をONにして。

> mac-demo-1の監視をOFFにして、実際に停止したか状態を確認して。

端末一覧の指示と実際の状態は別です。OFFの要求が成功しても、端末から停止報告が届くまでは停止完了と判断しません。`online`、`observed_state`、`revision`と`applied_revision`で確認します。実際にカメラを止めるのは端末側の処理です。

- 遠隔ONは、端末が接続中で、遠隔操作を許可し、カメラ確認画面が表示されている間だけ可能です。
- ページを隠す・閉じる、または遠隔許可を解除すると撮影を止めます。再び使う場合はローカルで許可し、新しいON指示を送ってください。
- OFFではAPIからの応答を待たずにカメラと撮影タイマーを止めます。通信失敗時もローカルの停止を優先します。
- 端末がofflineの間、OFF指示は保存できますが直ちに届く保証はありません。未処理ONには120秒の期限があり、古いONで勝手に再開しません。
- Macではブラウザを閉じた状態やバックグラウンドでの常時監視、Mac本体の電源操作はできません。

Reachy Mini / CoreS3も同じ[端末制御REST API](../../cloudflare-events/README.md#遠隔監視api)を使える設計ですが、各実機の撮影・停止・heartbeatアダプターは未実装です。既存の共通判定APIへの接続だけで遠隔制御が自動的に有効になるわけではありません。

## 見る項目

- 保持確率：画像内でスマホを手に持っているか。
- 可視性：手元を判定できる状態か。
- 継続時間：APIが新しい画像から確認した保持時間。画面のタイマーだけで通知しません。
- 応答時間とフレーム数：画像送信から応答までの時間と受理した応答数。
- 判定理由・ログ：不可視、API失敗、通知後の再検知などの確認用。

通知後のクールダウンはなく、次の画像から新たな2秒の確認を始めます。スマホを持ち続けた場合も繰り返し通知できます。画像の受理間隔が2.5秒を超えると継続時間はリセットされます。通信や推論の時間により、現実に持った瞬間から正確に2秒で通知される保証はありません。

## 接続と保存

カメラ画像はMac上のローカルサーバーを経由し、Cloudflare WorkerとOpenAIへ送信されます。UIとローカルサーバーは画像をファイルに保存しません。サーバーは `127.0.0.1` だけで待ち受け、公開サーバーとしては使いません。

Workerの `FOCUS_API_TOKEN` はローカルサーバーが保持し、ブラウザへ渡しません。`OPENAI_API_KEY` はCloudflareのSecretだけに設定します。ブラウザの保存領域へキーを保存する処理はありません。

Events連携の `FOCUS_EVENTS_TOKEN` もサーバーだけで保持します。検知APIの成功応答を先にブラウザへ返した後、通知メタデータを送信します。Events側が失敗しても画像判定・ローカル通知は止めません。送信待ちは最大64件のメモリーキューで、最大3回再試行します。プロセス終了や長い障害では未配送イベントを失う場合があります。

```sh
npm run test:mac-check
npm run test:events
```

ローカルプロキシの接続制限・秘密値の扱い・送信上限・イベント中継・遠隔指示の処理と、Events Workerを検証できます。

2026-10-18のChrome偽カメラ＋実判定APIの確認では、6フレームで2回通知し、それぞれ2,534ms / 2,386msの継続保持を確認しました。Mac用の自動テスト51件（プロキシ19・遠隔制御32）、ペアリング設定UIのモック7項目、遠隔操作UIのモックChrome10シナリオが通過しています。許可待ち中のOFF、非表示時の停止、期限切れ、別端末の選択も確認しました。期限切れONで121秒後にカメラ許可が返っても、API呼び出し・画像送信はありません。

Events Workerは配備済みで、`npm run smoke:events` の公開API試験12項目も通過しています。この試験は専用の偽端末を使います。

さらにChrome仮想カメラから実判定API・公開Events WorkerまでのE2E 7項目が通過しました。遠隔ONで検知を開始し、異なる通知2件をOAuthのイベント履歴でも確認しました。イベントは規定の8フィールドだけで画像を含みません。遠隔OFF後は全カメラトラック終了、フレーム送信停止、端末の実状態OFF・指示適用済みを確認しました。要求8件中7件の応答を受け、停止時に処理中の1件を取り消しています。ページエラー0、モバイルの横方向はみ出しなし、試験用OAuth認可は取り消し済みです。

これらは仮想カメラ映像を使った試験です。実際のdotsアカウントへの通知、実カメラでの遠隔操作、Reachy/CoreS3制御は未確認です。最新版の検証結果はPRの検証欄を参照してください。
