# Focus dance (0.3.0)

開発時は `origin/feat/shared-focus-api` の1352ce0から `codex/reachy-focus-dance` を作成し、[PR #11](https://github.com/aieo-product/devdayHackathon261018/pull/11)で統合した。現在の統合先は `main`。この機能追加ではAPI・Cloudflare・他デバイスを変更していない。

- 新しい画像が可視性0.7以上、スマホ確率0.2以下の非検出を返す時間が10秒続いたら、公式dance1を再生する。音声の設定に従い、終了後も条件が続けば繰り返す。
- ダンス中に、新しい画像が可視性0.7以上・スマホ確率0.8以上を返したら、notify=falseの最初の保持判定でもFearへ切り替える。リアクション途中の頭の姿勢を通常姿勢として保存しない。
- 受信した判定を処理してから次の動作指令を出す。画像応答が返るまでの撮影・ネットワーク・推論遅延は残る。
- 判定不能、低可視性、通信失敗、10秒の結果欠落、一時停止、終了、時間切れでもダンスを止める。停止後の遅延応答は無視する。
- 直後にサーバーの通知確定が届いても、再生中のFearを最初からやり直さない。プリセット音声後の日本語の声かけを維持する。
- スマホを置いたと確認できたら従来どおりcheerful1で喜び、新たなスマホなしの10秒確認を経てダンスへ戻る。
- プリセットは個別にロードし、dance1だけ利用できない場合もFear・喜びを無効化しない。操作画面にダンスの利用可否を表示する。

検証: Python47件（最初の保持応答による中断、判定不能・失敗・停止・遅延、音声停止とFearの重複再始動抑止を含む）。実機の見た目と画像判定を含む切り替えは導入後に確認する。
