# FOCUS DOTS 集中サポート

PCのWebブラウザで使う集中タイマーと通知画面です。ライム色のDOTSを1体表示し、共有APIのスマホ保持判定に合わせて、動くトースト・警告音・全画面リリックで作業への復帰を促します。別アプリの上に警告を表示するmacOS用の補助アプリも含みます。

このディレクトリはチームのMac向けフロント実装です。画像の判定処理は共有APIが担当し、Reachy Mini・CoreS3・AIBI実機の制御は含みません。

- [配備APIの仕様](https://focus-shared-api-20261018.take-otani.workers.dev/docs) / [OpenAPI](https://focus-shared-api-20261018.take-otani.workers.dev/openapi.json)
- [引き継ぎとマージ手順](docs/HANDOFF.md)
- [画像・効果音の由来](ASSETS.md)

## まず音と動きを確認する

Node.js 18以降が必要です。外部npmパッケージのインストールは不要です。

```sh
cd focus-dopa-preview
npm start
```

[音とアクションのデモを開く](http://127.0.0.1:4327/?pattern=fever&character=green&showcase=1) →「音つきで一通り再生」を押します。約33秒でトースト、開始、ジャンプ、一時停止、再開、休憩、節目、警告、完了、終了の10シーンを再生します。「トーストだけ」「警告＋トースト」でも個別に試せます。

このデモURLは初期表示でAPI接続確認・ネイティブ表示接続確認を行いません。デモ再生はカメラ、共有API、実セッション、通知件数を変更しません。停止ボタンまたはEscで動きと音を取り消します。音の開始にはクリック操作が必要で、OSやブラウザの消音設定にも従います。

通常画面は [こちら](http://127.0.0.1:4327/?pattern=fever&character=green)。サーバーは `127.0.0.1:4327` のみで待ち受けます。ポート変更は `FOCUS_PREVIEW_PORT` で指定します。これはローカル実行用であり、公開サイトへのデプロイは別作業です。

## 共有APIを設定する

`.env.example` に値を含まない設定例があります。共有トークンはGitに含めません。受け取り側で `focus-dopa-preview` の1階層上に `.env.focus-api.local` を作成し、チームから受け取った値を設定します。

```dotenv
FOCUS_API_URL=https://focus-shared-api-20261018.take-otani.workers.dev
FOCUS_API_TOKEN=REPLACE_WITH_TEAM_TOKEN
```

```sh
chmod 600 ../.env.focus-api.local
```

設定後にサーバーを再起動してください。環境変数が最優先、次に `../.env.focus-api.local`、最後にこのディレクトリ内の `.env.local` を参照します。上のトークン値は記入例で、そのままでは接続できません。

ブラウザは同一オリジンの `/api/focus` を呼び、Nodeサーバーが共有APIへ認証付きで中継します。フロントのHTML・JavaScript・URLへトークンを埋め込む必要はありません。この構成のためにAPI側のCORS設定を変更する必要もありません。`OPENAI_API_KEY` は共有API側の設定で、このフロントには保存しません。

中継先は上記の共有APIに限定しています。別のAPIホストへ変更する場合は、環境変数だけでなく `focus-api-proxy.mjs` の許可先とテストも変更してください。

## 実際のカメラで使う

1. 通常画面でモードを「共有API」にし、接続状態を確認します。
2. 「カメラを有効にする」を押し、このPCのカメラ利用を許可します。音声入力は使いません。
3. セッションを開始します。進行中かつカメラ有効時だけ、画像を指定の共有APIへ送ります。
4. 一時停止・休憩・終了で撮影と未完了の画像処理を止めます。再開後は必要に応じてカメラを再度有効にします。

画像は最大640×480、1 MiB以下のJPEGに縮小し、同時に1枚だけ送信します。画像をこのアプリのファイルへ保存しません。初期表示の机の画像はサンプルであり、カメラ映像ではありません。

**2026-10-18の最新仕様は「スマホを2秒継続保持・通知クールダウンなし」です。** 判定条件は共有APIが管理します。フロントは `next_capture_after_ms` に従って次の画像を送り、新しい画像応答の `notify: true` のみ通知します。`notification_id` による重複排除以外に、独自の保持時間や通知待機時間を追加しません。旧ダウンロード版の「5秒保持・60秒待機」を実APIへ再適用しないでください。

観測間隔が2500msを超えた場合の継続保持リセットもAPIの担当です。撮影・通信・推論には遅延があるため、物理的に持った瞬間から正確に2秒で鳴る保証ではありません。停止操作と画像の応答が重なった場合は、撮影を止め、遅れて届く応答から新しい通知を出さない処理を行います。

| モード | 判定・タイマーの扱い |
|---|---|
| 共有API | APIの判定結果を使用。現行実装では一時停止・休憩中も開始からの期限が進む |
| 演出デモ | ローカルタイマー。一時停止中は時間を止める。手動検知シミュレーションには旧60秒ゲートが残る |
| 音つき10シーンデモ | 演出のみ。上記タイマー・手動検知ゲート・実APIから独立 |

`unknown` は判定不能として表示し、警告へ変換しません。単なる身体の動き、机の上にあるスマホ、仕事目的かどうかをフロントで判定することもありません。通信エラー時は撮影を停止して状態の再確認を促します。

## トーストと小窓とデスクトップ表示

通知ONでAPIから新しい通知を受けると、小窓があれば小窓のバナーに、なければ表示中のWeb画面右下の動くトーストにAPIの通知文を表示します。同時に約5秒の警告リリックを出します。トーストは約8秒で閉じます。

「開始時に小窓を開く」は初期ONです。Document Picture-in-Picture対応のChromeでは、別アプリの上でもキャラ・残り時間・判定状態を確認できます。未対応ブラウザの別ウィンドウは最前面固定を保証しません。Codex内蔵ブラウザでは小窓が開いた直後に閉じる挙動を確認したため、小窓を使う場合はChromeで開いてください。

タブ切り替えや画面非表示ではセッション・有効化済みのカメラを止めません。元のタブ、ブラウザ、ローカルサーバーを開いたまま使います。ブラウザ終了後、PCスリープ中、ブラウザによる処理制限下での正確な通知時刻は保証しません。通知OFFは通知を抑止する設定で、撮影停止とは別です。

非アクティブ中に届いた警告は最新1件を最大60秒保持し、同じセッションの進行中に戻ると演出だけを無音で再表示します。この60秒は見逃した表示の有効期限で、API通知のクールダウンではありません。一時停止・休憩・終了・通知OFFで保留した警告も取り消します。

「デスクトップ通知を許可」を押すと、ブラウザが非表示中の検知と完了をOS通知でも知らせます。ブラウザ／OSの権限が必要です。ページ内トースト、小窓、OS通知、次のmacOS全画面表示はそれぞれ別の表示経路です。

### macOSの全画面警告

macOS 12以降、Xcode Command Line Toolsが必要です。生成済みのアプリやビルドキャッシュは配布対象に含めず、受け取り側でビルドします。

```sh
./desktop-overlay/build.sh
open "./desktop-overlay/build/Focus Desktop Overlay.app"
```

Nodeサーバーと補助アプリを起動すると、通常画面の「デスクトップにも、ドーン。」から接続を確認できます。「5秒後にデスクトップでテスト」を押して別アプリへ切り替えると、Macの画面全体に警告を表示します。クリックを通過させ、キーボードのフォーカスを奪わず、最長5秒で閉じます。補助アプリはメニューバーの✦から終了します。

補助アプリ未接続時はWeb画面内の警告へ戻ります。ロック画面やOSの保護された画面は対象外です。ローカル接続用の `.focus-overlay-bridge.json` はサーバーが配信ディレクトリ外へ生成します。詳細は [補助アプリのREADME](desktop-overlay/README.md) を参照してください。

## キャラと演出

キャラは `assets/todd.png` のDOTS1体です。メイン画面・トースト・小窓・通知アイコンで共通して使用し、トーストや小窓への表示中はメインのキャラを隠します。ロボット版の旧キャラは現行表示に使いません。

4パターンは `pattern=bounce`（弾む）、`rush`（速い残像）、`orbit`（浮遊）、`fever`（流星・花火）。演出量はOFF / POP / MAX、OSの動き軽減設定にも対応します。通常のリリックは単色のDOTS形に透過文字を重ね、警告時はアンバーの輪郭・警告レール・大きな文字へ切り替えます。

警告音は通常の効果音を中断して優先再生します。開始・再開・一時停止・休憩・終了・タップ・節目・完了には個別の短い効果音があります。音が不要な場合は画面右上でOFFにできます。

## 検証と実装の境界

```sh
npm test
```

2026-10-18時点で79テスト成功。API中継・APIクライアント・タイマー・通知の重複排除・古い応答の無効化・演出停止・音の優先制御・ネイティブ表示の橋渡し・デモの停止と再実行を確認しています。

実機では、共有APIの開始／取得／一時停止／再開／終了と、許可を受けた実カメラ画像の送信・判定を確認済みです。判定は `unknown` から `observing` に変化しました。**実際にスマホを保持した陽性判定から通知が発火する流れは未確認です。** カメラ確認後はセッションを終了し、映像トラックを解放しています。

Chromeの小窓表示と操作、動くトースト、デスクトップ警告、各演出は個別に確認しました。単体テストはカメラ認識精度、長時間のバックグラウンド動作、全OS環境での通知を保証しません。ログ・セッションID・通知数はページ内メモリのみで、再読み込み後の復元はありません。

ブラウザのOS通知は実装済みですが、実際のOSトースト表示は未確認です。仕様上のMac通知の受入確認では、ページ内トーストやMac全画面警告とは別に確認してください。
