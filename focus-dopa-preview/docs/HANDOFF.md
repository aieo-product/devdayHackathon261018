# Mac向けフロント実装の引き継ぎ

この変更は [aieo-product/devdayHackathon261018](https://github.com/aieo-product/devdayHackathon261018) に、PCブラウザ向けの集中支援画面を追加するためのものです。共有APIを使うフロントを `focus-dopa-preview/` にまとめ、機器側の実装と独立して起動・確認できる構成にしています。

## 仕様の基準

最新の動作条件は [Issue #1](https://github.com/aieo-product/devdayHackathon261018/issues/1) を基準にします。初期の [3機種仕様ページ](https://focus-team-spec-20261018-a14d.donald-25.chatgpt.site/) とダウンロード版API仕様書、2026-10-18のチーム議論も確認していますが、後から変更された通知条件を古い値へ戻さないでください。

配備APIは [仕様ページ](https://focus-shared-api-20261018.take-otani.workers.dev/docs) と [OpenAPI](https://focus-shared-api-20261018.take-otani.workers.dev/openapi.json) を公開しています。取り込み元のコミット `7fe1d70` のREADME・API契約には5秒／60秒の旧記載が残っているため、レビュー時は最新Issueと配備版の設定を照合してください。

| 項目 | 最新仕様とこの実装の扱い |
|---|---|
| スマホ保持 | 最新Issueは2秒継続保持。判定は共有APIで行う |
| 通知クールダウン | 最新Issueはなし。実API経路にクライアント側の待機時間を追加しない |
| 次の画像送信 | 応答の `next_capture_after_ms` に従う。同時送信は1枚 |
| 観測間隔が2500ms超 | APIが継続保持の進捗をリセット。フロントの経過時間で補わない |
| 警告の発火 | 新しい画像応答の `notify: true` と未処理の `notification_id` の組み合わせ |
| 停止と遅延応答 | STOP／END操作で撮影・後続通知を止め、古い応答を破棄する |
| 旧「5秒・60秒」 | ダウンロード版の旧条件。実APIへ適用しない |
| デモ用60秒ゲート | `session.js` の手動検知シミュレーションにのみ残る。実APIの合否判定に使わない |
| 見逃し演出の60秒保持 | 非アクティブ中の最新1件を後で表示する期限。通知のクールダウンではない |

`cooldown` というAPI状態名は互換性のためクライアントが受け付けますが、それを根拠に60秒の独自タイマーを開始しません。共有API側の変更は共有API側で検証し、この画面で同じ判定を二重実装しない構成です。

## チーム議論と仕様への対応

文字起こしの内容は設計上の要点だけを以下へまとめています。原文、個人名、会場・参加者情報、会話の私的な部分は配布対象に含めません。

| 議論または仕様の要点 | この変更に含むもの | 残る範囲 |
|---|---|---|
| デスク上のカメラでスマホ利用を捉え、作業へ戻るきっかけをつくる | PCカメラ → 共有API → 通知の接続 | スマホ保持の実カメラ陽性テスト |
| 特定のロボットがなくても使える | PCのブラウザだけでタイマー・判定・通知を利用 | Reachy MiniとCoreS3の単独動作はそれぞれの担当実装 |
| 各端末が同じAPIへ画像を送り、自分の端末で通知する | Macの画像送信とMac内のアクションを接続 | 他機種の通信をこのMac経由へ集約しない |
| 簡単な開始設定と結果が見える画面 | 開始・停止・休憩、接続状態、判定状態、イベントログ | 永続履歴と複数端末の統合管理は未実装 |
| APIで確認できた保持進捗を表示する | 判定状態と理由を表示。独自タイマーで進捗を増やさない | `continuous_hold_ms` / `required_hold_ms` の数値表示は未実装 |
| 動きがあり、通知に気づきやすいデザイン | DOTS1体、ゲージ、4演出パターン、警告音優先、リリック | 効果の有効性評価は行っていない |
| PCでポップアップと音を出す | ページ内トースト、Chrome小窓、任意のOS通知、Mac補助アプリ | OS通知権限は利用者が設定。各表示経路を混同しない |
| まず見守りを作り、リアルタイム会話は後から追加 | 画像判定と短い通知を優先 | 音声入力・自由会話は対象外 |
| チームで1つのリポジトリに集め、ブランチからPRでマージ | 独立ディレクトリとこの引き継ぎ文書 | 受け取り側でレビューして統合 |
| AIBIなど別の機器も検討する | この変更には実機接続を含めない | AIBI調査は別作業。必須3機種の完成と同一視しない |
| 公開URLとソースで成果を確認できるようにする | ソースとローカルデモ手順 | 公開サイトのデプロイと提出は別途必要 |

Issueの担当分担では、フロント①がMacカメラとOSトースト、フロント②がセットアップ・セッション・状態表示を担当します。この変更は両者が接続できる画面とMacブラウザ経路を含みます。API＋CoreS3、Reachyの各担当の実装や受入確認を置き換えるものではありません。

## 起動してレビューする

リポジトリのルートから実行します。

```sh
cd focus-dopa-preview
npm test
npm start
```

[10シーンの演出デモ](http://127.0.0.1:4327/?pattern=fever&character=green&showcase=1) を開き、「音つきで一通り再生」を押します。約33秒で一通り確認でき、カメラ・実APIは使いません。最初にこれを確認すれば、トークンをまだ受け取っていなくてもフロントのレビューができます。

実APIの確認は [READMEの設定手順](../README.md#共有apiを設定する) に従い、共有トークンをローカルに設定してサーバーを再起動します。通常画面で接続確認を行い、実カメラの送信は利用者の許可を得てから開始してください。

## マージ手順

提出はforkの作業ブランチから、チームリポジトリの統合先ブランチへのPull Requestで行います。取り込み準備では `feat/shared-focus-api` のコミット `7fe1d70` を参照しています。PRのbaseがチームの統合対象になっていることを確認してください。既存のバックエンド・Reachy Mini・CoreS3のコードを置き換えず、このディレクトリを追加する単位でレビューします。

1. Pull Requestの「Files changed」で、対象が `focus-dopa-preview/` の現行コード・必要アセット・ドキュメントであることを確認します。
2. PRのブランチをチェックアウトし、上記の `npm test` と音つきデモを実行します。
3. 共有トークンをレビュー側の環境に設定し、開始・一時停止・再開・終了、判定状態、通知の重複抑止を確認します。
4. Macの外部表示が必要なら、`bash ./desktop-overlay/build.sh` でビルドして起動し、デスクトップ表示テストを確認します。
5. APIのスマホ陽性判定と通知を別途確認し、未確認のままマージする場合は残課題として記録します。UIのデモ成功を認識精度の検証済みと扱わないでください。
6. 受け取り側の通常のレビュー手順で、PRに指定した統合先へマージします。共有APIの通知条件をこのPR側で変更する必要はありません。

静的なGitHub Pagesへ置くだけでは、Nodeの認証付き中継やMac補助アプリは動きません。公開デモを作る場合は表示だけのデモと実API運用を分け、実API運用では同等の認証・送信先制限を持つサーバーを別途用意します。現行サーバーのlocalhost制限を外すだけで公開しないでください。

## 確認済みと未確認

| 確認項目 | 結果 |
|---|---|
| 自動テスト | 2026-10-18時点で79件成功 |
| APIの開始・取得・一時停止・再開・終了 | 確認済み |
| 実カメラの画像取得・共有API送信・応答表示 | 確認済み。`unknown` → `observing` を確認 |
| スマホの実物保持 → 陽性判定 → 実通知 | 未確認 |
| DOTSトースト・警告リリック・効果音・10シーンデモ | 動作確認済み |
| Chrome小窓・小窓からの操作 | 確認済み。Codex内蔵ブラウザには小窓互換性の制限あり |
| ブラウザ経由のOSトースト | 実装済み。OS上の実表示は未確認で、ページ内トーストや全画面警告とは別に受入確認が必要 |
| Mac補助アプリのデスクトップ警告 | 確認済み。実API陽性からの一連の通知は別途確認が必要 |
| カメラの長時間バックグラウンド動作・PCスリープ | 長時間保証なし。スリープ中の継続は対象外 |
| Reachy Mini・CoreS3・AIBIの実機動作 | この変更の検証対象外 |

実カメラの確認後はセッション終了と映像トラック解放を確認しています。現在のログと通知件数はページ内メモリのみで、リロード後には復元しません。API接続では休憩・一時停止中もセッション期限が進みます。ローカルデモでは時間が止まるため、この違いもレビュー時に確認してください。

APIキー・共有トークン・`.env`系の実設定・`.focus-overlay-bridge.json`・実カメラ画像・文字起こし原本・旧試作キャラ・生成済みアプリ・ビルドキャッシュは含めません。受け取り側で作る設定ファイルもGitへ追加しないでください。
